description: What the 2.0.0 rename changes and what you need to do about it.
---

Both predecessor plugins are archived and superseded by this one. Their code lives on as the Forms
and Push modules, but 2.0.0 renames every identifier so that this reads as one plugin rather than
two bolted together.

## Everything is renamed

<Callout type="warn">
	2.0.0 renames every identifier onto a single `mrdw` namespace. Anything integrating with the
	previous plugins — or with 1.4.0 — has to be updated. There is no automatic data migration.
</Callout>

The two predecessors are gone as separate identities. What used to be `packrelay_*` is now
`mrdw_forms_*`, what used to be `tailsignal_*` is now `mrdw_push_*`, and the two REST namespaces
have collapsed into one.

| Was                                   | Is now                        |
| ------------------------------------- | ----------------------------- |
| `packrelay/v1`, `tailsignal/v1`       | `mrdw/v1`                     |
| `PackRelay_*`, `TailSignal_*` classes | `MRDW_Forms_*`, `MRDW_Push_*` |
| `packrelay_settings`                  | `mrdw_forms_settings`         |
| `tailsignal_expo_access_token`        | `mrdw_push_expo_access_token` |
| `tailsignal_manage` capability        | `mrdw_manage`                 |
| `{prefix}packrelay_entries`           | `{prefix}mrdw_forms_entries`  |
| `{prefix}tailsignal_*` tables         | `{prefix}mrdw_push_*`         |
| `packrelay-entries` page slug         | `mrdw-form-entries`           |
| `tailsignal-*` page slugs             | `mrdw-push-*`                 |
| `mrdemonwolf` text domain             | `mrdw`                        |

### The app must be updated

The REST paths themselves are unchanged in shape — only the namespace segment moved:

```diff
- POST /wp-json/packrelay/v1/submit/{form_id}
+ POST /wp-json/mrdw/v1/submit/{form_id}

- POST /wp-json/tailsignal/v1/register
+ POST /wp-json/mrdw/v1/register
```

### Data is not migrated

The new tables are created empty on activation. Entries and devices held by PackRelay, TailSignal or
1.4.0 are **not** carried across. If you have data worth keeping, export it first — Form Entries has
a CSV export, and Devices has one under Push Settings.

## What changes

| Change      | Detail                                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| Admin menu  | The two top-level menus are gone. Everything is under one **MrDemonWolf** menu.                                         |
| Text domain | All three domains collapse into `mrdemonwolf`. Custom translation files need renaming.                                  |
| PHP floor   | 8.3. Required by the Firebase SDK the Forms module depends on; PackRelay's declared 8.1 was never actually installable. |
| Updates     | Both hand-rolled updaters are replaced by one checker with stable and nightly channels.                                 |
| Expo token  | Can now be supplied by a `wp-config.php` constant instead of the database.                                              |
| Page hooks  | Admin page hook suffixes are now `mrdw_page_*`. Only matters if you wrote custom code against them.                     |

## Steps

1. Export anything you want to keep. Form Entries has a CSV export; Devices has one under Push
   Settings. Nothing is carried across automatically.
2. Deactivate PackRelay and TailSignal. **Do not delete them yet** — deleting runs their uninstall
   routines and drops their tables, taking your only copy of the data with them.
3. Install and activate this plugin. Its own tables are created empty.
4. Re-import your devices under **MrDemonWolf → Devices** if you exported them.
5. Update the app to call `/wp-json/mrdw/v1/...`.
6. Once you are satisfied, delete the old plugin _directories_. Deleting through the WordPress admin
   would trigger their uninstall scripts, so remove the folders over SFTP or WP-CLI instead:

```bash
wp plugin delete packrelay --skip-plugins --skip-themes
```

<Callout type="warn">
	Take a database backup before any of this. `--skip-plugins` stops the uninstall hook running, but
	a backup is the only thing that makes a mistake recoverable.
</Callout>

## Conflict guard

While either predecessor is still active, this plugin registers no hooks at all and shows an admin
notice naming the conflicting plugin. That is deliberate: both define the same PHP classes, so
loading them together would be a fatal error rather than a warning.
